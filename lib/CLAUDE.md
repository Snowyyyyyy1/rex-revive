# lib/
> L2 | Parent: ../CLAUDE.md

The engine. Dependencies point one way: util ← proc ← agents ← snapshot ← restore ← closed, and agents ← titles. revive.lua loads them through `package.path`.

util.lua: the base layer. Files with atomic writes, JSON that never raises, `rex.exec` output, POSIX quoting, UTC times (`iso`, and `epoch`, its inverse, which adds the local offset back as os.time reads tables as local time), the state directory, notifications, and `log`, which also appends to `log_file` when a palette run sets it. Its only rex-revive knowledge: where state lives, and the notification title.
proc.lua: the only reader of OS process state. `names` reads Rex's process fields (argv0, script, invoked_path, name). ps gives age and command line; lsof gives open files, run only for the pids that need them; /proc on Linux. Fills what Rex's `terminal.process` omits: start times, full argv, open files.
agents.lua: the only module that knows coding agents: Claude Code, Codex, pi, Gemini CLI, Droid, amp, Cursor Agent, opencode. REGISTRY entry per agent (match, ID check `valid` (UUID by default; amp's `T-<uuid>`, opencode's `ses_<letters and digits>`), pid-record folder, held-file rule, argv rule, kept options, resume command). `valid` guards every ID that reaches a typed command. `identify` tries pid record → held file → argv; `running` finds chats open anywhere; `key` is the one spelling of "agent:session". Rex's `string.match` returns no value on a miss, and `tonumber()` with no argument raises: wrap a match in parentheses before `tonumber`.
snapshot.lua: the reader side. `collect` attaches with `session.attach_all{event_scope="session"}`, walks tiled layouts, keeps this host's terminals only (block host_id equals server host_id). Each pane in a split gets `place`: its side, the split's direction and ratio, and `anchor`, the ID of the split's other side (a block or a split), which keeps its ID when the pane closes. `describe` turns a process chain into shell, program, or agent. `idle_shell` asks about one block only (one process call, no ps or lsof): an idle shell with no agent in its chain. Saves keep non-shell panes, one file per server instance, newest 10; pruning runs only when an instance adds a file. `save` returns the save it replaced, for closed.lua's diff. That file is overwritten on every save, so `checkpoint` copies it to `history/<saved_at>.json` at most every 30 minutes and only when what runs changed (a signature of each pane's session, kind, agent, session ID, command, folder), newest 48; file names sort by time, so it reads only the newest copy. `saves` lists both kinds, newest first, each with `id`, its path under the snapshots folder, which is what `from=` names.
restore.lua: the writer side, the only module that types into terminals. `where` names a pane ("work tab 2 pane 1") for logs and rows. `id` names what a question lists: a chat's key, or `program:<block>`; `only` and `leave` use ids. `plan` is pure: match by block ID, then by session label and position; skip busy tabs, open chats, and ids in `leave` (unticked in the question). `pending` lists the saved chats not open anywhere, then the programs, from the save alone, so it works while restored tabs start. `run` re-collects and re-plans up to 10 times, 3 s apart, while restored shells settle, and returns the chats it typed. `into_tab` types a closed chat into its own block when `idle_shell` says it is free, with a `cd` first when the shell sits elsewhere, then focuses it. `open` starts a closed chat in a new pane: `session.attach` first (a script must attach before it adds a pane), then `session.new_split` beside `place.anchor` when the chat's session is the target, else `session.new_window`; both with `cwd` and `initial_input`.
titles.lua: the only reader of the agents' conversation files, for the rows of the question. Claude: the last rename, else the last AI title, read from the last 4 MB of the file (files reach 500 MB; the last title sat within 0.6 MB of the end in 376 real chats), else the first prompt. Codex: `threads.name` in ~/.codex/state_N.sqlite through sqlite3, else the first prompt. pi: the first prompt. Gemini: the first prompt of the ~/.gemini/tmp/*/chats file whose first line names the session. amp: the thread file's title, else its first prompt. Droid: `title` on the first line (session_start) of ~/.factory/sessions/<folder>/<id>.jsonl. Cursor Agent: the first user message in ~/.cursor/chats/<md5>/<id>/store.db (blobs, by rowid, through sqlite3) that closes `<user_query>…</user_query>` (Cursor's instructions name the tag too, unclosed; its meta name stays "New Agent"), and `updatedAtMs` from meta.json for `idle`. opencode: `session_v2.title` and `time_updated` (ms) in ~/.local/share/opencode/opencode.db through sqlite3; its ID is checked to be `ses_` and letters and digits, so it is safe in the query. `idle` and `ago` come from the file's mtime or Codex's updated_at. It runs only when a person is asked, never on a save, and a failure leaves the title out.
closed.lua: the memory of closed chats, `closed.json`, newest first, at most 20. `diff` (pure) compares a save with the one it replaced: chats it lost are closed, chats it has are not. `merge` (pure) puts newly closed chats in front, moves a chat closed again to the front, and drops chats back in a tab; `update` writes only on a change. An entry keeps the pane fields that `restore.text` and `restore.running` read, `block_id` and `place` (where to reopen it), and `closed_at`. `update` returns the entries it added, for the log.
