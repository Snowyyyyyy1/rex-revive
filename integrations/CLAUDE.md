# integrations/
> L2 | Parent: ../CLAUDE.md

Code that runs inside another program, not inside `rex do`. Each file talks to the engine only through files or the `rex` command.

rex_revive.lua: Rex config actions. install.sh fills @REX@ and @SCRIPT@ and copies it to ~/.config/rex/. `revive_choose` has two callers. From the palette, it runs `mode=choices`, asks with `rex.ui.pick{multiple=true}`, then starts `mode=restore only=…`. From the watcher after a restart, `rex do revive_choose --args {items}` (chats and programs) asks in every connected Rex app and returns `{keys}` only when someone pressed Reopen. `rex.ui.pick` works only in an action's own body: never in pcall, rex.on, or rex.invoke. Rex requires a `title` on every action and has no hidden action, so the watcher reuses this one. `row` draws a chat (its title from lib/titles, else its folder; `detail` how long ago it was active) or a program ("typed, not run"); it sets `selected` from revive.lua's `ticked`, and only in a multiple pick, as Rex allows it nowhere else. In a multiple pick ⌘↩ answers, so the filter's placeholder says so. `revive_reopen_closed` runs `mode=closed` and asks with a single pick; `revive_reopen_last` reopens the newest. Both start `mode=reopen session=<ctx.session_id>`, so the tab opens where the person is. ⇧⌘T is bound to `revive_reopen_last` only when `rex.bindings` shows no earlier binding of it. `revive_settings` asks with a single pick whether to ask after a restart and writes it with `mode=settings ask=…`. Every action has a `description` for the palette.
pi-rex-revive.ts: the pi extension behind pi's pid records. On session_start (UI sessions only) it writes ~/.pi/agent/rex-revive/<pid>.json with sessionId, startedAt from process.uptime, and pi's argv, which pi hides from ps; it removes the file on quit. No network, no output.
